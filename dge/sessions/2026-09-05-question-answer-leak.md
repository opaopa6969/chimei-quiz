# 機械生成設問の正解一意性・事実正当性DGE

## 観測対象

chimei-quiz は公開データ（Wikidata / e-Stat自治体変遷 / 番地の謎）から 3,851 問を機械生成し、
Remotion 演出付きの4択で配信する。`docs/market/2026-08-22.md` は「自治体変遷（vanished 2,123問 +
timeline-reason 741問）という、既存の手作りサイトが作れない量のニッチジャンルを独占できているか」が
唯一の勝負所だと結論している。

したがって本DGEの観測対象は「勝負所カテゴリの設問が、クイズとして実際に成立しているか」に置いた。
UI・性能・運用も同時に観測したが、判断の中心は設問そのものの正当性である。

計測環境: Node v24.20.0 / `npm test` 48 pass 0 fail / `npm run build` 成功 /
`node scripts/build-quiz-sets.mjs` を無改変で再実行して `public/data/quiz/` に差分が出ないこと
（＝コミット済み生成物がバイト単位で再現すること）を確認済み。

### 第一幕: 「3,851問ある」は本当に価値か

**葵:** 遊んでみて最初に困ったのは、結果画面に何問正解したかが出ないこと。`ResultScreen.jsx:9` は
「10問中プレイ」としか出ない。スコアだけ見せられても、自分が上達したのか分からない。

**澄:** それは小さく直せる。回答履歴を `GameScreen` で持って結果画面に出すだけだ。純粋な追加で、
消せば元に戻る。最小・安全・可逆の条件を全部満たす。今回はこれでいいのでは。

**環:** 待ってほしい。その前に設問を読んだか。`timeline-merge-釧路市-2005-10-11` の問題文は
「釧路市・阿寒町・音別町が合併して誕生したのは？」で、正解は釧路市だ。問題文に答えが書いてある。

**律:** 何問だ。

**環:** 実測で 189/741、timeline-reason の 25.5%。merge に限れば 189/484 で約4割。しかも
`portmanteau.mjs:13` は `!ev.olds.some(o => o.name === ev.new.name)` で**同じケースを明示的に弾いている**。
同じデータ・同じイベント型を扱う隣のジェネレータが弾いている条件を、`timeline-reason.mjs:19` だけが
弾いていない。設計の抜けではなく、実装の取りこぼしだ。

**葵:** それは効く。4問に1問は問題文を読むだけで解ける。演出を2.5秒見せられた末にそれだと、
「このクイズは作り込まれていない」と感じてやめる。

**澄:** ただ、その修正は生成データの再生成を伴う。差分が大きくなってレビューできないのでは。

**岳:** それはこのrepoでは既定路線だ。PR #8（`81613e9`）は distractors.mjs の6行修正で
`all.json` を19,290行入れ替えている。生成物をコミットする設計を選んだ以上、ジェネレータ修正＝
大きな生成差分は規約どおり。重要なのは**レビュアが手元で再現できるか**で、それは今日確認した。
無改変で `build-quiz-sets.mjs` を再実行すると差分ゼロになる。

### 第二幕: 復習機能を先に入れてはいけない理由

**澄:** それでも、正答数と「間違えた問題だけ復習」は利用者が毎回体感する。設問の質は詳しい人しか
気づかない。優先順位は逆ではないか。

**環:** 逆ではない。復習機能は「間違えた問題を優先的に繰り返し提示する装置」だ。いま復習に回るのは
何か。`vanished-朝日町-北海道` は「次のうち、現在は存在しない市町村はどれ？」の正解が朝日町だが、
朝日町は山形県・富山県・三重県に現存する。この種が 148/2,123 問ある。正しく知っている人ほど×になり、
その×が復習キューに積まれて、**誤った知識を反復学習させられる**。

**葵:** それは嫌だ。自分が正しいのに間違い扱いされて、しかもそれを覚え直させられるのは最悪の体験だ。

**律:** 加えて、正答率という数字自体が現状では上達を測らない。`difficulty` は vanished 全2,123問が
0.6、portmanteau 全296問が0.7、reading 全99問が0.6 とカテゴリ定数で、`buildSession`
（`quiz-engine.js:27`）は単純シャッフルだ。正答率は「その日どのカテゴリが混ざったか」の関数にしかならない。

**澄:** 分かった。復習機能は取り下げる。ただし「その前に設問を直す」と言うなら、直す対象は
1つに絞ってほしい。誤問は他にもあるのだろう。

### 第三幕: どの誤問を今日直すか

**環:** 誤問は少なくとも3系統ある。(a) timeline-reason の正解露出 189問、(b) vanished の正解が
他県に現存 148問、(c) `data/municipality-master.json` に廃止済み自治体が5件混入
（浦和市112046・岩舟町093670・宮城村103055・竜洋町224839・植木町433853）していて誤答プールに入り、
二重正解を作っている。

**岳:** (c) にはもっと悪い話がある。PR #15（issue #11）の重複解消は
`fetch-wikidata-municipalities.mjs:126-129` で「人口が大きい方を残す」tie-break を使った。その結果
`泊村|北海道` で**北方領土の国後郡泊村（016969、人口5,595＝1945年国勢調査値）を採用し、現存する
古宇郡泊村（014036）をマスタから消している**。色丹村1,499人・蘂取村0人など北方領土6村が
「現存自治体」として city-fact に入り、`city-fact-population-asc-016951`「次のうち人口が一番少ない
のは？」の正解が色丹村になっている。該当11問。

**律:** つまり過去の修正の副作用だ。しかしそれを直すには Wikidata を取り直す必要がある。

**岳:** そのとおり。`fetch-wikidata-municipalities.mjs` はライブSPARQLで、前回取得は2026-08。
いま取り直すと**意図した修正と、8月以降の上流データのドリフトが同じ差分に混ざる**。しかも
`build:data` は取得日もソースcommitも記録していないので、差分のどこが自分の変更でどこがWikidataの
更新か、レビュアにも自分にも切り分けられない。これは今日のPRに入れてはいけない。

**澄:** すると (a) だけが「入力データがコミット済みで、再生成が決定論的に再現でき、上流ドリフトが
混ざらない」条件を満たす。(b) も同じ条件だが。

**環:** (b) は文面の設計判断が要る。「次のうち現在は存在しない市町村はどれ？」を全国スコープで
問いながら、判定は `vanished.mjs:22` の `name|prefecture` で県内スコープという食い違いが原因だ。
prompt に県名を入れて「現在北海道に存在しない市町村は？」にすると、誤答は全国の現存自治体だから
**4択全部が正解**になって壊れる。148問を落とすのか、誤答プールを県内に絞るのか、prompt を作り直すのか、
この場で決めるべきではない。

**律:** (a) は違うのか。

**環:** (a) は違う。修正が一意に決まる。新設合併で新市名が旧自治体名と同一（吸収的新設合併）の
ケースで、**正解と同名の旧自治体だけを問題文の列挙から外す**。「阿寒町・音別町と合併して誕生したのは？」
になり、事実は保たれ、問われる知識（阿寒町・音別町がどこに合併したか）はむしろ純化する。

**葵:** 189問が消えるのか。変遷推理は勝負所なのに。

**環:** 消えない。実測で 188件すべて、同名を除いても旧自治体が1件以上残る（残り1件が73、2件が45、
3件が32…最大11件）。捨てずに全部出題できる。

**律:** 189問目は。

**環:** `timeline-merge-那賀町-2005-03-01`「鷲敷町・相生町・上那賀町・木沢村・木頭村が合併して
誕生したのは？」正解 那賀町。完全一致ではなく、**上那賀町が那賀町を部分文字列として含む**ケースだ。
だから条件は「同名を外す」ではなく「正解名を部分文字列として含む旧名を外す」にすべきで、そうすれば
`prompt.includes(answer)` が偽であることを**不変条件として保証できる**。

**澄:** 全部外すと0件になるイベントは。

**環:** 2件ある。`[上湧別町・湧別町] → 湧別町` と `[有田町・西有田町] → 有田町`。これは
どう書いても問題文に答えが出るので出題不能、スキップする。741 → 739 問。

**岳:** absorb 側は。

**環:** 257件中0件。merge だけの問題だ。

**澄:** ならこれを採用する。ジェネレータ1ファイル・条件1つ・文面1つ。テストと再生成が付く。
revert 一発で戻る。

### 第四幕: 反論の残り

**律:** 都道府県タグを使った「ご当地モード」はどうだ。tags には 3,544/3,851 問に県名が入っていて、
`docs/question-patterns.md:103` は「pref=北海道 だけの北海道編」を設計として書いている。UIから
一切使われていないのは明白な設計と実装の差だ。

**環:** 却下したい。`vanished.mjs:52` の誤答は全国の現存自治体名プールから引く。「北海道編」と
銘打った瞬間、正解は常に北海道の自治体なので「4択のうち北海道っぽい名前」を選べば当たる。
same-name に至っては 57問全部が答えそのものが都道府県名だ。ご当地モードを入れるなら
**誤答プールを県内に絞る改修が前提**で、それは今日の1意味単位に収まらない。

**葵:** 演出スキップは。1問あたり intro 2.5秒＋result 2.0秒で操作不能、10問で45秒。しかも
vanished 2,123問は問題文が全部同じ一文で、それをタイプライターで打つのを何十回も見せられる。

**岳:** それは分かるが、順序は転送量が先だ。`server.js:64-68` は gzip も ETag も付けず、
`all.json` 3,823,680B を無圧縮で返している（gzip すると 335,460B、11.4倍）。しかも `no-cache` を
返しながら検証子が無いので条件付きGETが成立せず、再検証が毎回フル200になる。演出を先に飛ばすと、
ロードの待ち時間がむき出しになる。

**澄:** どれも本物だが、今日の1意味単位ではない。記録して次に回す。

**律:** 最後に一つ。この修正は「利用者が体感する」と言えるのか。

**葵:** 言える。いま変遷推理を10問遊ぶと、期待値で2〜3問は問題文を読むだけで正解できる。それが
消えるのは、遊んだ瞬間に分かる違いだ。むしろ「難しくなった」と感じるはずで、それが正しい。

## tramli / tramli-appspec 適合性

独立調査で両者の実体と公開状況を確認した。

**tramli**（opaopa6969/tramli, public, npm `@unlaxer/tramli` 3.9.0 / crates.io / Maven Central）は
制約付きフローエンジン。FlowState / StateProcessor / TransitionGuard / BranchProcessor / FlowContext /
FlowDefinition / FlowEngine / FlowStore の8要素と、Auto / External（外部event待ちで一時停止）/ Branch
の3遷移＋SubFlow を持ち、各 processor の `requires()` / `produces()` を `build()` 時に全経路検証する。

**tramli-appspec**（opaopa6969/tramli-appspec, private, Java/Maven）は tramli の上に載る AppSpec
バリデータ兼パイプラインオーケストレータ。CREATED→…→CODEGEN_APPROVAL→COMPLETED/BLOCKED の
PipelineState を持ち、人間レビューと承認を前提とする。DATA / PROJECTION / RUNTIME_POLICY /
CODEGEN_APPROVAL の4段は worker 未実装のスタブで、レジストリ公開実績が無くソース参照のみ。

|---|---|---|

照らして Pipeline API すら不要な側に落ちる。**抽象化のためだけには導入しない。**
